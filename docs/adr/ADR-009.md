# ADR-009 — AUTO / ASSISTED / MANUAL as the Only Application Modes

## Context
Job application platforms vary enormously in what automation can
legitimately achieve — some support full unattended submission, some
require human interaction partway through, some cannot be automated at
all without violating platform terms or defeating anti-automation
controls (doc 01 §7).

## Decision
Exactly three modes (doc 03 `ApplicationMode`): `AUTO`, `ASSISTED`,
`MANUAL`. Every job's `applicationMethod` and every candidate's automation
preference resolve into exactly one of these three — no partial or hybrid
mode type.

## Alternatives Considered
- **A continuous automation-confidence score instead of discrete modes**:
  rejected — discrete modes map directly to distinct UI experiences (doc
  01 §56–58) and distinct execution paths (doc 11 §2); a continuous score
  would still need to be bucketed into UI/execution decisions somewhere,
  so the discretization is better done explicitly and early.
- **More granular modes (e.g., separate "auto with confirmation" mode)**:
  the same effect is achieved via `automationMode` + `approvalRequired`
  (doc 11 §4) layered on top of the three execution modes, avoiding a
  combinatorial explosion of mode types.

## Consequences
Manual Handoff (doc 15) is elevated to a first-class, well-designed
success path rather than an afterthought error case — directly serving
doc 01 §7's non-negotiable boundary against defeating anti-automation
controls.
