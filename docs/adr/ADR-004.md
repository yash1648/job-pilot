# ADR-004 — pgvector for Semantic Retrieval

## Context
Matching (doc 09) and RAG retrieval (doc 06 §4) need approximate nearest-
neighbor search over candidate/job/company embeddings.

## Decision
pgvector extension on the primary PostgreSQL instance, `ivfflat` indexes
(doc 04 §4) tuned per table.

## Alternatives Considered
- **Dedicated vector database**: better raw ANN performance at very large
  scale, but introduces a second store to keep consistent with the
  relational data (ADR-003's rationale) — deferred until doc 32 §5's scale
  signal is observed.

## Consequences
Embeddings and their source entities are transactionally consistent
(same DB, same transaction possible). Index tuning (`lists` parameter) is
an ongoing operational task as row counts grow (doc 31 §4).
