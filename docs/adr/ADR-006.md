# ADR-006 — Playwright for Java (Browser Agent)

## Context
The Browser Agent (doc 14) needs reliable, modern browser automation with
strong support for dynamic/JS-heavy application forms (doc 13), and must
integrate cleanly with the Java-first stack (ADR-002).

## Decision
Playwright for Java as the Browser Agent's automation engine.

## Alternatives Considered
- **Selenium**: mature but weaker built-in support for modern JS-heavy
  page patterns and auto-waiting semantics that Form Intelligence (doc 13)
  relies on; explicitly what doc 01 says this product is *not* ("do not
  build a Selenium bot").
- **A separate Node.js browser-worker service using Playwright's native
  JS bindings**: would split the stack and require a service boundary
  (network calls, serialization) between the browser layer and the rest of
  the application purely for tooling reasons, not an architectural need —
  rejected in favor of staying in-process within the Java stack, consistent
  with ADR-002.

## Consequences
Single-language stack maintained end to end (ADR-002). Playwright's Java
API is less commonly used than its JS/Python bindings, meaning smaller
community reference material — mitigated by doc 28's dedicated fixture/
evaluation suite substituting for community-tested confidence.
