# ADR-010 — Evidence-Grounded Generation (Zero-Fabrication Enforcement)

## Context
Any AI-generated claim about the candidate (resume bullet, cover letter
sentence, application answer) that isn't true is a serious real-world harm
to the candidate — potential misrepresentation, damaged credibility, or a
failed background check. Prompting a model to "be truthful" is not a
reliable technical control on its own.

## Decision
Every generation output schema (doc 06 §6) requires an `EvidenceRef` on
each substantive claim; the Policy Engine (doc 16 §4) independently
validates each reference resolves to real candidate evidence and that
claim specificity doesn't exceed what the evidence supports (doc 23 §4).
Unvalidated claims are rewritten or routed to user review — never
persisted as-is.

## Alternatives Considered
- **Prompt-only enforcement ("never fabricate," in the system prompt)**:
  rejected as the sole control — insufficient given the stakes; kept as a
  first-layer instruction but never relied upon alone.
- **Post-hoc human review of all generated content before any use**:
  rejected as the only control — doesn't scale to the product's automation
  ambitions (doc 01 §5.15) and doesn't stop a fabricated claim from ever
  being generated, only from being seen uncaught.

## Consequences
Generation pipelines (doc 12) require additional schema/validation
engineering versus naive prompt-and-return generation. Doc 27 tracks
hallucination rate as the tightest-tolerance metric in the eval suite,
reflecting this decision's priority.
