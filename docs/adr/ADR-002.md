# ADR-002 — Java-First Architecture

## Context
The system requires strong typing across a large domain model (doc 03),
long-lived stateful workflows (doc 17), and a browser automation layer
(doc 14) that benefits from Playwright's mature Java bindings.

## Decision
Java 21+ with Spring Boot 3.x as the primary implementation language and
framework across all modules.

## Alternatives Considered
- **Node.js/TypeScript**: strong Playwright support natively, but weaker
  fit for the heavily-typed domain model and long-running stateful
  workflow orchestration this product needs; would also split the stack
  (browser layer vs. everything else) without a clear benefit.
- **Python**: strong AI/ML ecosystem, but weaker fit for the transactional,
  strongly-typed domain core and production web-application concerns
  (doc 22 security, doc 04 schema discipline).

## Consequences
Consistent tooling/testing/build story across the whole system (doc 26,
doc 33). AI provider calls are HTTP-based (doc 06 §1), so Java's weaker
native ML ecosystem is not a practical constraint — the model runs in
Ollama, not in-process.
