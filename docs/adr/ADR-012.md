# ADR-012 — MCP as a Future Adapter, Never a Business-Logic Layer

## Context
The product roadmap (doc 36 Phase 13) anticipates exposing JobPilot
capabilities to external AI clients via MCP, but building MCP support
prematurely, or embedding business logic inside MCP tool handlers, risks
creating a second, divergent code path around the Policy Engine and
approval controls (doc 11 §4, doc 16 §4).

## Decision
MCP is deferred (FUTURE tier) and, when built, implemented strictly as a
thin adapter calling the same service interfaces the REST API (doc 05)
calls — no MCP tool contains logic the REST layer doesn't also enforce
(doc future/01-mcp-readiness.md §2–3).

## Alternatives Considered
- **Build MCP early, in parallel with the REST API**: rejected — doubles
  the surface area needing Policy Engine/security review before either is
  proven correct, and risks the two surfaces drifting in behavior.

## Consequences
MCP integration work is postponed until the readiness checklist (doc
future/01-mcp-readiness.md §5) is met, at which point it should be a
comparatively small adapter-layer effort rather than a redesign.
