# ADR-003 — PostgreSQL as Primary Database

## Context
The domain model (doc 03) is heavily relational (Application ↔ Job ↔
CandidateProfile with strict invariants, doc 03 §6) and additionally needs
vector similarity search (doc 09 matching).

## Decision
PostgreSQL 16+ as the single system-of-record database, with pgvector
(ADR-004) for embeddings — one database technology for both relational and
vector needs rather than two separate stores.

## Alternatives Considered
- **Separate vector DB (e.g., a dedicated vector store) + relational DB**:
  rejected for the initial architecture — adds operational complexity and
  a consistency-synchronization problem (keeping embeddings in sync with
  their source rows across two stores) that pgvector avoids by co-locating
  the data.
- **NoSQL document store**: rejected — the domain's relational invariants
  (doc 03 §6, doc 04 constraints) are exactly what a relational database
  enforces natively; a document store would push that enforcement into
  application code with weaker guarantees.

## Consequences
One database to operate, back up, and reason about transactionally (doc
33 §6). Revisit pgvector-at-scale per doc 32 §5 if vector query performance
becomes the bottleneck a dedicated vector store would solve.
