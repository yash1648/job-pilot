# ADR-005 — Ollama as Initial AI Provider

## Context
The product processes highly sensitive personal data (doc 24) through
every AI-touching pipeline; it also needs a provider abstraction (doc 06
§1) that doesn't lock the architecture to one vendor.

## Decision
Ollama (self-hosted) is the initial AI provider for all `AiTaskType`
routing profiles (doc 06 §2), behind the `AiService`/`EmbeddingService`/
`VisionService` interfaces.

## Alternatives Considered
- **Hosted API provider from day one**: faster access to frontier model
  quality, but means candidate resume/job/application content leaves the
  infrastructure boundary by default (doc 24 §7) — a materially different
  privacy posture the product isn't required to accept just to launch.

## Consequences
Strong privacy property (doc 24 §7) stated explicitly to users. Requires
self-hosted GPU/compute capacity (doc 33) and accepts a potentially lower
ceiling on raw model quality versus the largest hosted models — mitigated
by doc 06 §2's model routing (using the strongest available local profile
only where reasoning depth actually matters) and doc 27's eval suite
catching quality regressions. A hosted provider can be added later as a
second `AiService` implementation (ADR-007) without touching business
logic, and would be opt-in per doc 24 §7.
